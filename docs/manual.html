Bab 1: Pendahuluan & Arsitektur Sistem

SANTARA adalah aplikasi pemantauan kesehatan remaja SMA terintegrasi. Fokus utama sistem ini adalah pemantauan status gizi (antropometri), skrining kesehatan (kadar Hb anemia & tekanan darah), serta kepatuhan konsumsi Tablet Tambah Darah (TTD) pada siswa perempuan untuk mencegah anemia sejak dini.

1.1 Hak Akses Role (RBAC)

Sistem menerapkan pembatasan akses berbasis peran (Role-Based Access Control) yang terbagi menjadi tiga tingkatan resmi:

  • ADMIN: Memiliki kontrol penuh atas data murid, entri kesehatan, artikel edukasi, serta akses ke menu manajemen akun pengguna sistem (01_USERS).
  • GURU: Guru Kesehatan atau Petugas UKS. Berhak mencatat pemeriksaan gizi, skrining Hb/tensi, log konsumsi TTD, serta mengelola artikel edukasi kesehatan.
  • SISWA: Murid terdaftar. Hanya dapat mengakses dashboard pribadinya untuk melihat rekam medis kesehatan pribadi secara aman tanpa dapat melihat data murid lain.

1.2 Arsitektur Data Terintegrasi

Aplikasi ini dibangun menggunakan arsitektur serverless modern:

  1. Frontend (Next.js App Router): Dibangun dengan visualisasi data grafik responsif, route guard berlapis tingkat folder untuk mencegah bypass URL, dan antarmuka premium berbasis Tailwind CSS.
  2. Backend API (Google Apps Script): Berperan sebagai API Router yang menerima request RESTful (GET & POST) dari frontend.
  3. Database (Google Sheets): Bertindak sebagai database cloud utama. Setiap penulisan/pembaruan data dari website akan disinkronisasikan langsung dalam hitungan milidetik secara real-time ke lembar spreadsheet.

Bab 2: Panduan Akses Halaman & Fitur Aplikasi

2.1 Menu Publik (Tanpa Sesi)

Ketika pengguna membuka situs utama, terdapat 3 halaman yang dapat diakses secara bebas tanpa perlu melakukan login:

  • Beranda Utama (/): Menampilkan navigasi publik, deskripsi layanan SANTARA, statistik ringkas, dan tautan masuk ke aplikasi.
  • Materi Edukasi (/edukasi): Berisi pustaka artikel tips gizi, pencegahan anemia, dan panduan pola makan sehat bagi remaja yang ditulis oleh guru kesehatan.
  • Grafik Sekolah (/grafik): Menyajikan diagram visual persentase status gizi siswa (Normal, Obesitas, dll.) di sekolah-sekolah terdaftar secara agregat guna menjaga kerahasiaan data pribadi.

2.2 Portal Login & Pendaftaran Siswa Baru (/login)

Sistem login didesain aman dengan menyembunyikan pilihan akun secara visual. Pengguna dapat masuk melalui dua tab utama:

A. Form Masuk Akun

  • Pengguna memasukkan ID Pengguna atau Kode Siswa secara manual (contoh: USR001 untuk Admin, USR003 untuk Guru, atau STD001/12345 untuk Siswa).
  • Terdapat tombol "Masuk untuk Umum (Role Siswa)" yang akan mengarahkan pengguna secara otomatis ke portal siswa menggunakan akun demonstrasi umum jika siswa belum memiliki Kode unik.

B. Form Pendaftaran Siswa Baru

Siswa baru dapat mendaftarkan diri secara mandiri dengan mengisi:

  • Nama Lengkap & Jenis Kelamin (Laki-laki / Perempuan).
  • Asal Sekolah & Kelas (Dropdown dinamis yang memfilter kelas berdasarkan sekolah yang dipilih).
  • Kode Siswa / NISN (Digunakan sebagai kata sandi login di masa mendatang) & Tanggal Lahir.
Info Sinkronisasi: Saat pendaftaran diklik, sistem akan langsung mengirim data ke Google Sheets, membuat ID baru secara otomatis (misal: STD016), dan otomatis membawa siswa masuk ke dashboard pribadinya tanpa bug.

2.3 Dashboard Kader (ADMIN & GURU) (/kader/dashboard)

Dashboard ini adalah panel utama untuk guru dan administrator. Halaman ini berisi ringkasan cepat jumlah siswa, grafik sebaran status gizi, total skrining anemia, serta tautan cepat ke modul tindakan kesehatan.

2.4 Modul Layanan Kesehatan (Kader)

A. Data Siswa (/kader/data-siswa)

Pusat data siswa. Guru dan admin dapat mencari murid, menyaring berdasarkan sekolah dan kelas, serta menambahkan data siswa baru secara langsung.

B. Pemeriksaan Gizi (/kader/status-gizi)

Digunakan untuk mencatat berat badan (kg) dan tinggi badan (cm) siswa. Sistem akan otomatis menghitung nilai IMT (Indeks Massa Tubuh) secara real-time dan mengklasifikasikannya ke dalam status: Normal, Overweight, Obese, Thinness, atau Severely Thinness sesuai standar WHO.

C. Skrining Kesehatan (/kader/skrining)

Modul untuk mencatat pemeriksaan kadar Hemoglobin (Hb) anemia siswa perempuan (dalam g/dL) dan tekanan darah. Hasil skrining Hb akan dikategorikan secara otomatis menjadi Anemia atau Normal.

D. Kepatuhan TTD (/kader/ttd)

Digunakan untuk mencatat konsumsi mingguan Tablet Tambah Darah (TTD). Menampilkan daftar centang (checkbox) kehadiran konsumsi TTD mingguan per kelas yang sangat praktis bagi guru kesehatan.

2.5 Modul Manajemen Pengguna & Edukasi

  • Kelola Edukasi (/kader/edukasi-kelola): Fitur CRUD untuk menambah, mengedit, mempublikasikan, atau menghapus artikel kesehatan gizi.
  • Manajemen Pengguna (/admin/users): Eksklusif untuk ADMIN. Berisi daftar pengguna yang berhak mengedit data kesehatan (01_USERS). Demi alasan keamanan, perubahan role/password dikunci secara aman (read-only) di frontend untuk mencegah manipulasi.

2.6 Dashboard Pribadi Siswa (/siswa/dashboard)

Halaman khusus siswa yang terproteksi ketat. Ketika siswa login menggunakan Kodenya, sistem membatasi (mengisolasi) tampilan hanya untuk datanya sendiri. Siswa dapat melihat grafik perkembangan tinggi/berat badan dari waktu ke waktu, riwayat kadar Hb anemia, serta status kepatuhan minum TTD pribadinya secara interaktif.

Bab 3: Arsitektur Basis Data Google Sheets

3.1 Cara Mengakses Database Live

Database utama SANTARA disimpan dalam lembar kerja Google Sheets dengan ID Dokumen: SANTARA_DATABASE. Anda dapat mengakses spreadsheet tersebut menggunakan akun Google yang terdaftar dengan hak edit melalui link kolaborasi internal atau drive folder admin.

3.2 Kegunaan Tabel & Struktur Kolom

Berikut adalah kegunaan dari 9 tabel (sheet) utama yang saling berelasi di Google Sheets beserta detail fungsi kolomnya:

1. Tabel 01_USERS (Daftar Pengguna Sistem/Kader)

Menyimpan data staf (Administrator dan Guru Kesehatan) yang memiliki hak akses menulis dan mengedit data kesehatan.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Pengguna dengan prefix USR (contoh: USR001).
name String Nama lengkap pengguna / guru kesehatan.
email String Alamat email aktif (digunakan juga untuk login).
role String Hak akses peran pengguna: ADMIN atau GURU.
school_id String (Foreign Key) Berelasi dengan ID sekolah di sheet 02_SCHOOLS.
class_id String (Foreign Key) Berelasi dengan ID kelas di sheet 03_CLASSES (opsional).
status String Status aktif akun: active atau inactive.
created_at Timestamp ISO Tanggal dan waktu akun dibuat.

2. Tabel 02_SCHOOLS (Master Data Sekolah)

Menyimpan daftar sekolah SMA/sederajat yang bermitra dalam pemantauan kesehatan.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Sekolah dengan prefix SCH (contoh: SCH001).
name String Nama sekolah (contoh: SMA Negeri 1 Malang).
address String Alamat fisik sekolah.
city String Kota / Kabupaten letak sekolah.
province String Provinsi letak sekolah.
status String Status kerja sama sekolah (active / inactive).
created_at Timestamp ISO Tanggal dan waktu sekolah didaftarkan.

3. Tabel 03_CLASSES (Master Data Kelas)

Menyimpan data kelas di setiap sekolah beserta tahun akademik berjalan.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Kelas dengan prefix CLS (contoh: CLS001).
school_id String (Foreign Key) Berelasi dengan ID sekolah di sheet 02_SCHOOLS.
address String Lokasi gedung kelas (opsional).
academic_year String Tahun ajaran aktif (contoh: 2025/2026).
grade String / Number Tingkatan kelas (contoh: 10, 11, 12).
class_name String Nama rombongan belajar (contoh: IPA 1, IPS 2).
status String Status keaktifan kelas (active / inactive).
created_at Timestamp ISO Tanggal dan waktu kelas dibuat.

4. Tabel 04_STUDENTS (Data Murid)

Menyimpan data identitas siswa SMA yang dipantau.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Siswa dengan prefix STD (contoh: STD001).
school_id String (Foreign Key) Sekolah asal siswa (berelasi dengan 02_SCHOOLS).
class_id String (Foreign Key) Kelas asal siswa (berelasi dengan 03_CLASSES).
student_code String NISN atau kode unik yang digunakan siswa untuk login.
nama String Nama lengkap siswa.
gender String (L / P) Jenis Kelamin: L (Laki-laki) atau P (Perempuan).
birth_date Date String Tanggal lahir siswa (format: YYYY-MM-DD).
status String Status siswa (active / inactive).
created_at Timestamp ISO Waktu pendaftaran siswa.
updated_at Timestamp ISO Waktu data siswa terakhir diubah.

5. Tabel 05_EXAMINATIONS (Pemeriksaan Gizi Antropometri)

Menyimpan data rekam medis antropometri siswa (tinggi badan, berat badan, IMT).

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Pemeriksaan dengan prefix EXM (contoh: EXM001).
student_id String (Foreign Key) Berelasi dengan ID Siswa di sheet 04_STUDENTS.
class_id String (Foreign Key) ID Kelas siswa saat diperiksa (berelasi dengan 03_CLASSES).
examination_date Date String Tanggal dilaksanakannya pemeriksaan (YYYY-MM-DD).
weight_kg Number Berat badan siswa dalam satuan Kilogram (kg).
height_cm Number Tinggi badan siswa dalam satuan Sentimeter (cm).
bmi Number Nilai IMT hasil pembagian Berat (kg) / Tinggi kuadrat (m²).
nutrional_status String Typo dipertahankan: Klasifikasi WHO (Normal, Obese, dll.).
examiner_id String (Foreign Key) ID Guru/Kader pemeriksa (berelasi dengan 01_USERS).
notes String Catatan tambahan hasil pemeriksaan.
created_at Timestamp ISO Waktu data pemeriksaan dimasukkan ke database.

6. Tabel 06_SCREENINGS (Skrining Hb & Tekanan Darah)

Menyimpan log pemeriksaan Hb anemia dan tensi.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Skrining dengan prefix SCR (contoh: SCR001).
student_id String (Foreign Key) Berelasi dengan ID Siswa di sheet 04_STUDENTS.
class_id String (Foreign Key) ID Kelas siswa saat diskrining.
screening_date Date String Tanggal dilaksanakannya skrining.
screening_type String Jenis skrining: Anemia atau Tekanan Darah.
result String Hasil pengukuran (misal: 11.5 g/dL (Anemia) atau 120/80 mmHg).
notes String Catatan medis tambahan petugas.
examiner_id String (Foreign Key) ID Petugas pemeriksa (berelasi dengan 01_USERS).

7. Tabel 07_TTD (Pencatatan Konsumsi Tablet Tambah Darah)

Menyimpan riwayat kepatuhan konsumsi TTD mingguan bagi siswa perempuan.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik log TTD dengan prefix TTD.
student_id String (Foreign Key) Berelasi dengan ID Siswa di sheet 04_STUDENTS.
class_id String (Foreign Key) ID Kelas murid.
consumption_date Date String Tanggal pemberian / konsumsi obat (YYYY-MM-DD).
consumed Boolean / String Pernyataan minum obat (true / false atau Ya / Tidak).
quantity Number Jumlah tablet yang dikonsumsi (biasanya 1).
recorded_by String (Foreign Key) ID Guru perekam (berelasi dengan 01_USERS).

8. Tabel 08_EDUCATIONS (Materi Artikel Edukasi)

Menyimpan naskah artikel edukasi gizi dan kesehatan publik.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Artikel dengan prefix EDU.
title String Judul lengkap artikel edukasi.
slug String Pengenal ramah URL (contoh: cara-mencegah-anemia).
category String Kategori artikel (contoh: Nutrisi, Hb, TTD).
excerpt String Ringkasan pendek artikel yang tampil di kartu beranda.
content String (HTML/Text) Isi naskah lengkap artikel edukasi kesehatan.
thumbnail_url String URL Link gambar ilustrasi artikel.
status String Status publikasi (published / draft).

9. Tabel 09_AUDIT_LOG (Log Riwayat Perubahan)

Mencatat rekam audit setiap aksi penulisan data (Insert/Update) di website demi keamanan integritas database.

Nama Kolom Tipe Data Deskripsi / Kegunaan
id String (Primary Key) ID Unik Log dengan prefix LOG.
user_id String (Foreign Key) ID Pengguna yang melakukan aksi (berelasi dengan 01_USERS).
action String Jenis tindakan database (CREATE, UPDATE, DELETE).
table_name String Nama tabel spreadsheet yang diubah (misal: 04_STUDENTS).
record_id String ID dari baris record yang diubah.
description String Penjelasan aktivitas secara mendetail (contoh: Menambahkan siswa baru: Budi (12345)).
timestamp Timestamp ISO Waktu tepat aktivitas tersebut terjadi.
